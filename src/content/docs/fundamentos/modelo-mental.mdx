## La idea principal

Una interfaz construida con PelelaJS parte de una regla sencilla: **el estado es la fuente de
verdad**. La vista representa ese estado y los eventos expresan las acciones que pueden
modificarlo.

:::note[La regla más importante]
No modificás la pantalla para que los datos coincidan. Modificás los datos y PelelaJS actualiza la
pantalla mediante sus bindings.
:::

Los **bindings** conectan propiedades del ViewModel con elementos de la vista. Los **eventos**
conectan las interacciones del usuario con métodos del ViewModel. PelelaJS mantiene sincronizadas
ambas partes.

En una aplicación pequeña, el ViewModel puede contener todo el estado necesario. Cuando aparecen
reglas de negocio, conviene ubicarlas en modelos independientes y dejar que el ViewModel adapte sus
datos para la pantalla.

## Del evento a la vista

Cada interacción sigue el mismo recorrido:

```text
Interacción del usuario
        ↓
Evento declarado en el template
        ↓
Método del ViewModel
        ↓
Cambio de estado
        ↓
Actualización de los bindings
        ↓
Vista actualizada
```

Este flujo es unidireccional: la acción modifica el estado y el estado determina qué muestra la
vista. En los bindings bidireccionales, como `bind-value`, PelelaJS primero traslada al ViewModel el
valor ingresado por el usuario; el estado continúa siendo la fuente de verdad.

## Un ejemplo completo

El ViewModel contiene el estado del contador y la acción que lo modifica:

```ts title="counter.ts"
export class Counter {
  count = 0

  increment() {
    this.count += 1
  }
}
```

El template declara cómo mostrar ese estado y qué método ejecutar ante el evento:

```html title="counter.pelela"
<pelela view-model="Counter">
  <p>Contador: <strong bind-content="count"></strong></p>
  <button click="increment">Sumar</button>
</pelela>
```

Cuando la persona presiona **Sumar**:

1. El atributo `click="increment"` le indica a PelelaJS qué acción ejecutar.
2. PelelaJS llama al método `increment` del ViewModel.
3. El método modifica la propiedad `count`.
4. PelelaJS detecta el cambio de estado.
5. `bind-content="count"` actualiza únicamente el contenido del elemento asociado.

El método no necesita conocer el botón ni buscar el elemento que muestra el resultado. Su única
responsabilidad es expresar el cambio de estado.

## Separar responsabilidades

Una buena distribución permite entender cada parte sin recorrer toda la aplicación:

| Pieza | Responsabilidad |
| --- | --- |
| Modelo | Datos y reglas propias del problema. |
| ViewModel | Estado de presentación y acciones de la pantalla. |
| Template | Estructura, bindings y eventos declarativos. |
| CSS | Apariencia y adaptación visual. |
| PelelaJS | Reactividad y sincronización entre el ViewModel y el DOM. |

## Qué evitar

Si un dato forma parte de la interfaz, el ViewModel debería representarlo. Evitá cambiar el DOM
manualmente con `querySelector`, asignar `textContent` desde un método o guardar información sólo
en el HTML.

```ts title="Evitá modificar la vista directamente"
document.querySelector('#count').textContent = String(this.count)
```

```ts title="Modificá el estado"
this.count += 1
```

Este criterio mantiene separado el comportamiento de la presentación y hace que el código sea más
fácil de probar y extender.

en detalle las dos conexiones entre el ViewModel y la vista.
