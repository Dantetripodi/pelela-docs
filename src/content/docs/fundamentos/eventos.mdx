## Eventos

Los eventos llaman métodos del ViewModel. El método modifica el estado; el binding se ocupa de
reflejar el cambio.

```html
<button click="increment">+</button>
<button click="decrement">-</button>
```

```ts
increment() {
  this.counter++
}

decrement() {
  this.counter--
}
```

El atributo contiene únicamente el nombre exacto del método. No agregues paréntesis ni argumentos:

```html
<!-- Correcto -->
<button click="increment">+</button>

<!-- Incorrecto -->
<button click="increment()">+</button>
```

Pelela soporta dos eventos declarativos:

- `click`, sobre elementos HTML;
- `enter`, únicamente sobre elementos `input`.

```html
<input bind-value="name" enter="save" />
<button click="save">Guardar</button>
```

### Acceder al contexto y al evento

Pelela invoca el método con el ViewModel contextual como primer argumento y el evento nativo como
segundo argumento. Además, dentro de un método, `this` apunta al mismo ViewModel.

```ts
save(_viewModel: App, event: Event) {
  event.preventDefault()
  this.savedName = this.name
}
```

Esto es especialmente útil dentro de un `for-each`: el contexto incluye el elemento actual y el
índice declarado por la iteración.

```html title="app.pelela"
<li for-each="task of tasks" index="taskIndex">
  <button click="removeTask">
    Eliminar <span bind-content="task.title"></span>
  </button>
</li>
```

```ts title="app.ts"
type Task = {
  title: string
}

type TaskContext = {
  task: Task
  taskIndex: number
}

removeTask({ taskIndex }: TaskContext) {
  this.tasks.splice(taskIndex, 1)
}
```

No escribas `click="removeTask(task)"`: Pelela buscaría literalmente un método con ese nombre y
mostraría un error al ejecutar el evento.

Para formularios, la idea es la misma: el input mantiene el dato y `click` o `enter` dispara la
acción. Pelela no evita por sí solo el comportamiento nativo del navegador; si lo necesitás, usá
el segundo argumento del handler y llamá a `event.preventDefault()`.

## Una secuencia para depurar

1. ¿El elemento tiene el atributo de evento?
2. ¿El nombre coincide exactamente con el método?
3. ¿El método cambia una propiedad observada?
4. ¿La vista tiene el binding correcto?
