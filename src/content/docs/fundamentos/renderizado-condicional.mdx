## Renderizado condicional

Una interfaz no siempre muestra lo mismo. El binding `if` permite mostrar u ocultar un elemento
según una propiedad, getter o ruta de propiedades del ViewModel.

```html
<button click="toggleDetails">Ver detalles</button>

<section if="showDetails">
  <h2 bind-content="title"></h2>
  <p bind-content="description"></p>
</section>
```

```ts
export class App {
  showDetails = false
  title = 'Información extra'
  description = 'Este bloque depende de showDetails.'

  toggleDetails() {
    this.showDetails = !this.showDetails
  }
}
```

### Qué ocurre

Pelela usa la conversión booleana de JavaScript. Cuando el valor es falsy, asigna `display: none`.
Cuando vuelve a ser truthy, restaura el valor original de `element.style.display`. Si el elemento
no tenía un `display` inline, restaura el valor vacío y vuelve a aplicarse el display definido por
CSS o por el navegador. El elemento no se elimina ni se vuelve a crear.

`if` no evalúa expresiones de JavaScript. Si la condición requiere una comparación, colocala en
un getter:

```ts
get hasDescription() {
  return this.description.length > 0
}
```

```html
<p if="hasDescription" bind-content="description"></p>
```

Pensalo como una pregunta sobre el estado:

```text
valor truthy → se muestra
valor falsy  → se oculta
```

Por ejemplo, `''`, `0`, `null`, `undefined` y `false` ocultan el elemento. Un array vacío es truthy
y lo muestra.

### Buenas prácticas

- Usá una propiedad booleana con un nombre que explique la condición.
- Usá un getter cuando la condición dependa de una comparación.
- Poné en el bloque solo el contenido que depende de esa condición.
- Separá “qué se muestra” de “qué evento cambia la condición”.
- Probá siempre los dos estados, incluido el estado inicial.
