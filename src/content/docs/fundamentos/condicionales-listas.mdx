## Condicionales y listas

Las interfaces reales muestran estados vacíos, mensajes de error y colecciones. Pelela permite
expresar esas variantes desde el template.

## Mostrar u ocultar

```html
<p if="loading">Cargando...</p>
<p if="errorMessage" bind-content="errorMessage"></p>
```

La condición debe ser una propiedad, un getter o una ruta de propiedades cuyo valor pueda
interpretarse como verdadero o falso. La lógica de la condición pertenece al ViewModel, no al HTML.

## Repetir elementos

```html
<ul>
  <li for-each="task of tasks">
    <span bind-content="task.title"></span>
  </li>
</ul>
```

```ts
tasks = [
  { title: 'Leer la guía', done: false },
  { title: 'Resolver el ejercicio', done: false },
]

get hasTasks() {
  return this.tasks.length > 0
}

get hasNoTasks() {
  return this.tasks.length === 0
}
```

La sintaxis de la iteración es siempre `item of collection`. Pelela no evalúa comparaciones ni
operadores dentro de los atributos: para condiciones como “la lista está vacía”, definí un getter
en el ViewModel y usalo mediante `if="hasNoTasks"`.

La colección también puede ser una ruta anidada:

```html
<li for-each="task of project.tasks">
  <span bind-content="task.title"></span>
</li>
```

Si la propiedad no existe o su valor no es un array, Pelela muestra un error durante el montaje.
Una colección vacía, en cambio, es válida y no genera elementos.
