## Requisitos

Antes de empezar, verificá que tu entorno tenga:

- Node.js 22 o superior;
- pnpm 10 o superior.

Podés comprobar las versiones instaladas con:

```bash
node --version
pnpm --version
```

## Crear una aplicación con el CLI

El CLI es el recorrido recomendado para crear una aplicación nueva. Genera un proyecto completo
con Vite, TypeScript, PelelaJS, el plugin oficial y un ejemplo inicial.

Instalá el CLI globalmente:

```bash
pnpm add -g @pelelajs/cli
```

Creá el proyecto y ejecutalo:

```bash
pelela init "Mi App"
cd mi-app
pnpm install
pnpm dev
```

Abrí la dirección que informa Vite, normalmente `http://localhost:5173`.

El CLI normaliza el nombre recibido para que pueda utilizarse como nombre de directorio y de
paquete: lo convierte a minúsculas, reemplaza espacios y caracteres no admitidos por guiones, y
elimina guiones repetidos o ubicados en los extremos. Por eso `"Mi App"` crea `mi-app`.

El proyecto generado ya incluye:

- los scripts `dev`, `build` y `preview`;
- el plugin de PelelaJS configurado en Vite;
- las declaraciones de TypeScript para los templates `.pelela` y el módulo virtual;
- una pantalla de ejemplo;
- un archivo de rutas y el inicio del router.

La estructura resultante contiene los archivos de integración necesarios:

```text
mi-app/
├── index.html
├── main.ts                 # punto de entrada y montaje/router
├── routes.ts               # rutas de la aplicación
├── vite.config.ts          # plugin de PelelaJS
├── tsconfig.json
├── pelela-env.d.ts         # tipos de .pelela y del módulo virtual
├── package.json
├── styles.css              # estilos globales importados por main.ts
└── src/
    ├── components/         # componentes reutilizables
    ├── app.pelela          # template
    ├── app.ts              # ViewModel
    └── app.css             # CSS asociado automáticamente a App
```

No necesitás crear ni configurar esos archivos a mano cuando usás el CLI.

## Agregar PelelaJS a un proyecto existente

Si ya tenés un proyecto con Vite y TypeScript, podés incorporar PelelaJS sin generar una
aplicación nueva. Este recorrido contiene únicamente los cambios necesarios para integrarlo.

### Instalar las dependencias

```bash
pnpm add pelelajs
pnpm add -D vite-plugin-pelelajs
```

Si el proyecto todavía no usa TypeScript, instalalo también como dependencia de desarrollo.

### Agregar el plugin de Vite

El plugin transforma los templates `.pelela` y genera el módulo de autorregistro.

```ts title="vite.config.ts"
import { defineConfig } from 'vite'
import { pelelajsPlugin } from 'vite-plugin-pelelajs'

export default defineConfig({
  plugins: [pelelajsPlugin()],
})
```

Este paso es exclusivo de la integración manual. El CLI ya genera `vite.config.ts` con el plugin
configurado.

### Declarar los módulos de PelelaJS

TypeScript no conoce por sí mismo los archivos `.pelela` ni el módulo virtual del plugin. Agregá
estas declaraciones en `pelela-env.d.ts`:

```ts title="pelela-env.d.ts"
declare module '*.pelela' {
  export const viewModelName: string
  const template: string
  export default template
}

declare module 'virtual:pelela-auto-register' {
  export {}
}
```

El CLI también genera este archivo automáticamente.

### Crear el ViewModel y el template

El nombre indicado por `view-model` debe coincidir exactamente con el nombre exportado por la
clase.

```ts title="src/app.ts"
export class App {
  message = 'Hola, PelelaJS'

  changeMessage() {
    this.message = 'La vista se actualizó'
  }
}
```

```html title="src/app.pelela"
<pelela view-model="App">
  <main class="card">
    <h1 bind-content="message"></h1>
    <button click="changeMessage">Cambiar mensaje</button>
  </main>
</pelela>
```

El CSS que comparte el mismo nombre base que el template se asocia automáticamente con ese
componente:

```css title="src/app.css"
.card {
  max-width: 32rem;
  margin: 4rem auto;
  padding: 2rem;
  border: 1px solid #d9d9d9;
  border-radius: 0.75rem;
}
```

La asociación determina cuándo se carga la hoja de estilo, pero no encapsula ni transforma sus
selectores. Usá clases específicas para evitar colisiones entre componentes.

Los estilos globales no se asocian a un componente. Por eso se importan expresamente desde
`main.ts`:

```css title="styles.css"
body {
  margin: 0;
  font-family: system-ui, sans-serif;
}

button {
  padding: 0.6rem 1rem;
}
```

### Iniciar PelelaJS

El HTML del proyecto debe tener un elemento que funcione como raíz, por ejemplo
`<div id="app"></div>`. Después importá el autorregistro y montá el template desde el punto de
entrada:

```ts title="main.ts"
import './styles.css'
import { mountTemplate } from 'pelelajs'
import 'virtual:pelela-auto-register'
import template from './src/app.pelela'

const root = document.getElementById('app')

if (!root) {
  throw new Error('No se encontró el elemento #app')
}

mountTemplate(root, template)
```

El import `virtual:pelela-auto-register` ejecuta el código generado por el plugin para registrar
los ViewModels y componentes detectados. Debe ejecutarse antes de montar el template o iniciar el
router. Este código corresponde a la integración manual; el proyecto generado por el CLI ya usa
el autorregistro e inicia el router.

## Contrato del autorregistro

El autorregistro actual no recorre subdirectorios. Para que una pantalla o componente sea
detectado automáticamente debe cumplir todas estas condiciones:

1. Los archivos `.ts` y `.pelela` deben estar directamente dentro de `src`.
2. Ambos archivos deben compartir exactamente el mismo nombre base, por ejemplo `app.ts` y
   `app.pelela`.
3. El archivo TypeScript debe exportar una clase cuyo nombre coincida exactamente con el
   `view-model` del template.
4. Escribí `view-model` con comillas dobles. El autorregistro actual utiliza esa forma para
   descubrir el nombre de la clase.
5. El CSS es opcional. Si existe, debe compartir el mismo nombre base y estar junto al par, por
   ejemplo `app.css`.

Por el momento, no coloques pares que dependan del autorregistro dentro de `src/components/` u
otro subdirectorio: el plugin no los encontrará. Una estructura con subdirectorios requiere
registrar esos componentes manualmente.

## `mountTemplate` o `router.start`

Usá `mountTemplate(root, template)` cuando la aplicación tenga una única pantalla o cuando estés
aprendiendo los fundamentos sin navegación.

Usá `router.start(root, routes)` cuando la aplicación tenga varias rutas. En ese caso:

- registrá primero las pantallas mediante `virtual:pelela-auto-register`;
- definí un arreglo de rutas;
- no llames también a `mountTemplate`, porque el router se ocupa de montar la ruta activa.

El proyecto creado por el CLI ya utiliza `router.start`. La sección de routing explica su
configuración completa.
